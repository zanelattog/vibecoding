# Por onde começar


Antes de escolher plugin, vale responder: o que precisa funcionar e como vou perceber que funcionou?

## Se ainda é uma ideia

Escreva quem vai usar, qual problema existe, qual é o primeiro fluxo e o que fica para depois. Em uma lista de tarefas, o primeiro fluxo pode ser adicionar um item, marcar como concluído e desfazer. Login e sincronização são outras tarefas.

O toolkit original propõe Next.js como ponto de partida para novos projetos web. Isso não significa que todo aplicativo precisa dessa tecnologia. Um aplicativo de desktop e um site têm necessidades diferentes.

## Se o aplicativo já existe

Primeiro faça um inventário: como abrir, como testar, quais arquivos têm instruções, onde ficam os dados e quais serviços externos são usados. Preserve a linguagem, o banco e os comandos que já funcionam, a menos que exista uma razão clara para mudar.

Escolha uma melhoria pequena e verificável. Registre o comportamento atual e o resultado esperado antes de alterar. O [modelo de projeto](../../modelos/pt/projeto.md) ajuda a delimitar esse trabalho.

## Se falta preparar o computador

Confirme sistema, arquitetura do processador, ferramentas já disponíveis e o projeto que será aberto. Instale apenas os requisitos necessários, seguindo a documentação atual da ferramenta. Registre versão, origem, onde foi instalada e um teste de uso.

Abrir um arquivo de instruções não instala tudo. Conectar uma conta não garante que todos os agentes tenham acesso a ela. Um ambiente configurado também não prova que a aplicação funciona.

## Antes de começar

- Escolha uma pasta de trabalho e preserve uma cópia recuperável dos arquivos importantes.
- Separe exemplos fictícios de dados reais e identifique as ações que enviam mensagens, publicam ou alteram serviços.
- Use uma primeira tarefa pequena para conferir a instalação.
- Termine registrando o que funcionou e o que ainda depende de acesso ou configuração.
