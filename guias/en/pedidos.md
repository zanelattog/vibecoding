# 15 adaptable requests

Replace bracketed fields. These requests are an editorial library for this edition, not a literal copy of the original prompts. They do not install tools or independently authorize publishing data.

## 1. Understand an idea

> Explain the problem, audience and smallest useful workflow for [project]. Separate supplied facts from assumptions and propose acceptance criteria before implementation.

## 2. Prepare the machine

> Inspect the environment for [project] without changing it. List what works, what is missing, each installation scope and verification. Present required changes before installing.

## 3. Start a project

> Define the first delivery for [project] based on [need]. Propose a compatible structure and explain dependencies. After the decision, implement the agreed workflow and record completed checks.

## 4. Organize an existing project

> Read instructions and inspect [project]. Identify technologies, commands and observable problems. Preserve working behavior and propose gradual improvements without implicit migrations.

## 5. Refactor a section

> Review [section] and propose separation of responsibilities that preserves behavior. Make only the agreed change and check its effects on callers.

## 6. Address large files

> Inspect [files] by responsibility, not just size. Propose splits that reduce coupling and preserve existing interfaces and tests.

## 7. Adopt quality rules

> Check current rules and commands in [project]. Measure existing issues and propose gradual adoption of compatible rules without disabling protections to pass checks.

## 8. Resolve warnings

> Reproduce warnings from [command]. Separate pre-existing issues from the current change, fix in-scope items and rerun affected checks.

## 9. Review a change

> Review [change] read-only. Look for concrete failures and explain impact, evidence and location. Distinguish confirmed issues from questions and style preferences.

## 10. Divide work among agents

> Assess whether [task] has independent parts. If the environment supports it and delegation is authorized, assign goals and non-overlapping files; give one owner integration and final verification. Otherwise proceed sequentially.

## 11. Record context

> Summarize confirmed decisions for [project] in existing documents. Include rationale, relevant files, checks and pending work. Do not record secrets or copy the entire conversation.

## 12. Check the interface

> Exercise [workflow] with fictional data. Check empty states, errors, keyboard use and relevant screen sizes. Record observed results; do not send messages or change real services during the demonstration.

## 13. Review security

> Perform a read-only review of [authorized scope]. Examine input handling, authentication, permissions and secrets. Deliver evidence and recommendations in a private report; do not exploit external systems.

## 14. Check agent configuration

> Compare declared capabilities of [environment] with those available. Run a small case without sensitive data and separately record configuration, discovery and execution.

## 15. Improve the workflow

> Choose a repeated problem in [workflow] and record a baseline. Change one instruction or tool at a time and compare results on the same case. Keep only changes with observed benefit.
