# Where to start


Before choosing a plugin, answer: what needs to work, and how will I know it works?

## If it's still an idea

Write down the audience, problem, first workflow and what can wait. For a task list, the first workflow might be adding an item, marking it complete and undoing the change. Login and synchronization are separate tasks.

The original toolkit proposes Next.js for new web projects. This does not mean every application needs it. Desktop applications and websites have different requirements.

## If the application already exists

First inventory how to run it, how to test it, where instructions and data live, and which external services it uses. Keep the language, database and commands that already work unless there is a clear reason to change them.

Choose a small, verifiable improvement. Record current behavior and the expected result before editing. The [project template](../../modelos/en/projeto.md) helps define this work.

## If the computer needs preparation

Check the operating system, processor architecture, existing tools and intended project. Install only necessary prerequisites, following current tool documentation. Record version, source, installation scope and a usage check.

Opening an instruction file does not install everything. Connecting an account does not guarantee access for every agent. A configured environment also does not prove the application works.

## Before starting

- Choose a working folder and preserve a recoverable copy of important files.
- Separate fictional examples from real data and identify actions that send messages, publish or change services.
- Use one small task to check the installation.
- Finish by recording what worked and what still needs access or configuration.
