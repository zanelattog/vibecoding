# Practice exercises

These fictional exercises help apply the guide. They do not represent delivered projects or completed tests with every tool.

## 1. A small project, one agent

**Goal:** create a task list that supports adding, completing and deleting an item.

Define what should happen with empty input and whether the list must remain available after closing the page. Choose technology for that scope. A prototype without persistence does not need a database.

**Verification:** add two different items, complete only one, delete the other and attempt to add empty text. Record expected and observed results.

**Delivery:** run instructions, application files and a record of completed checks.

## 2. The same project, independent tasks

**Goal:** review the project without concurrent edits to the same file.

One review can check copy and keyboard navigation; another can inspect adding and deleting rules. The coordinator collects findings and decides the correction order. If splitting costs more than it helps, keep one agent.

**Verification:** each finding needs a reproducible action and observed effect. Final review checks behavior after integrating fixes.

## 3. An additional tool

**Goal:** find out whether a browser tool adds a missing check.

First record how the interface is checked today. Consult current documentation for the selected option and check compatibility and permissions. After authorized setup, exercise the same small workflow.

**Delivery:** separately record whether the tool was installed, discovered by the client and used successfully. Compare the evidence with the previous baseline.

## What these exercises do not prove

These are proposed activities. They do not establish professional experience, use of every tool, complete security or compatibility with every computer.
